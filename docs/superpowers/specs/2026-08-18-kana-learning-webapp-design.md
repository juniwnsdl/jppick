# 가나 쓰기 학습 웹앱 PRD

- 문서 상태: MVP 기준 확정안
- 작성일: 2026-08-18
- 대상 플랫폼: 반응형 웹(데스크톱, 모바일 브라우저)
- 후속 플랫폼: iPhone 앱

## 1. 제품 개요

히라가나와 가타카나를 처음 배우거나 다시 익히려는 사용자가 전체 가나를 찾아보고, 마우스 또는 손가락으로 직접 쓰면서 문자 형태와 발음을 반복 학습하는 웹앱이다.

첫 버전은 `글자표 + 자유 연습` 구조로 만든다. 계정이나 강제 학습 코스 없이 사용자가 원하는 문자 범위와 연습 방식을 직접 선택하고 바로 학습할 수 있어야 한다.

## 2. 해결하려는 문제

- 입문자는 가나의 형태, 발음, 획순을 한곳에서 확인하기 어렵다.
- 복습자는 원하는 문자만 짧게 반복해서 쓰는 도구가 필요하다.
- 종이 연습은 준비와 기록 관리가 번거롭고, 일반 퀴즈 앱은 실제 쓰기 경험이 부족하다.
- 자동 손글씨 판정은 편리하지만 초기 정확도와 구현 비용이 높다.

따라서 MVP는 문자 탐색, 직접 쓰기, 모범 글자 비교, 자기 평가에 집중한다.

## 3. 목표 사용자

### 3.1 입문 학습자

- 히라가나와 가타카나를 처음 배우는 사람
- 문자표, 발음, 획순을 확인하며 따라 쓰고 싶은 사람
- 학습 순서를 강제받기보다 원하는 행이나 문자부터 연습하고 싶은 사람

### 3.2 복습 학습자

- 가나를 배웠지만 일부 문자가 헷갈리는 사람
- 발음만 보고 문자를 떠올려 쓰는 연습이 필요한 사람
- 짧은 시간 동안 무작위 문제를 반복하고 싶은 사람

## 4. 제품 목표와 성공 조건

### 4.1 제품 목표

1. 사용자가 앱을 연 뒤 10초 안에 글자표를 보거나 쓰기 연습을 시작할 수 있다.
2. 초보자는 모범 문자를 보며 따라 쓰고, 복습자는 발음만 보고 회상 연습을 할 수 있다.
3. 사용자는 자신의 글씨와 모범 글자를 겹쳐 비교하고 스스로 결과를 기록할 수 있다.
4. 새로고침하거나 다시 방문해도 같은 기기에서 학습 기록이 유지된다.
5. 모바일 브라우저에서 손가락으로 자연스럽게 쓸 수 있고 데스크톱에서는 마우스나 펜 입력을 사용할 수 있다.

### 4.2 MVP 성공 지표

서버 분석 도구를 붙이기 전에는 브라우저 안에서 다음 수치를 계산해 기록 화면에 보여준다.

- 첫 연습 세션 완료율
- 세션당 완료 문제 수
- 7일 내 재방문 여부
- 문자별 연습 횟수
- 자기 평가 기준 성공률
- `다시 연습`으로 표시된 문자 수와 재연습 완료율

초기 제품 검증은 입문자와 복습자를 포함한 최소 5명을 대상으로 진행한다. 이 중 4명 이상이 별도 설명 없이 연습을 시작하고, 10문제 세션을 끝내며, 정답 비교 기능을 올바르게 사용해야 한다.

## 5. MVP 범위

### 5.1 포함

- 히라가나·가타카나 전체 글자표
- 문자별 발음, 로마자, 분류, 획순 안내
- 마우스·터치·스타일러스 기반 쓰기 캔버스
- 따라 쓰기 모드와 암기 테스트 모드
- 가나 종류와 문자 그룹 필터
- 중복을 최소화한 무작위 문제 출제
- 모범 글자 오버레이와 사용자 자기 평가
- 연습 결과와 어려운 문자 재연습
- 브라우저 로컬 저장소 기반 학습 기록
- 반응형 모바일 UI와 기본 접근성

### 5.2 제외

- 자동 손글씨 인식 또는 정답 판정
- 회원가입, 로그인, 클라우드 동기화
- 단계별 코스, 해금, 점수 경쟁
- 단어, 문장, 문법 학습
- 친구, 랭킹, 공유 기능
- 광고, 구독, 결제
- 네이티브 iPhone 앱

## 6. 문자 범위

`전체 가나`는 현대 일본어 학습에 쓰이는 다음 범위를 의미한다.

- 기본 히라가나·가타카나 46자씩
- 기본 가나의 탁음·반탁음과 `ゔ`, `ヴ`
- 요음 조합: きゃ/キャ, ぎゃ/ギャ, しゃ/シャ, じゃ/ジャ, ちゃ/チャ, にゃ/ニャ, ひゃ/ヒャ, びゃ/ビャ, ぴゃ/ピャ, みゃ/ミャ, りゃ/リャ 계열의 `ゃ・ゅ・ょ` 조합
- 작은 모음과 작은 가나: ぁぃぅぇぉゕゖっゃゅょゎ, ァィゥェォヵヶッャュョヮ
- 가타카나 장음 기호: ー
- 외래어 확장 조합: イェ, ウィ/ウェ/ウォ, ヴァ/ヴィ/ヴェ/ヴォ/ヴュ, キェ/ギェ, クァ/クィ/クェ/クォ, グァ, シェ/ジェ, スィ/ズィ, チェ, ツァ/ツィ/ツェ/ツォ, ティ/テュ, ディ/デュ, トゥ/ドゥ, ニェ, ヒェ/ビェ/ピェ, ファ/フィ/フェ/フォ/フュ, ミェ, リェ

역사적 가나와 일반 입력 환경에서 쓰이지 않는 특수 표기는 MVP에서 제외한다.

촉음과 장음 기호처럼 단독 발음이 없는 항목은 글자표와 따라 쓰기에는 포함한다. 암기 테스트에서는 단독 한글 발음 대신 `작은 つ`, `장음 기호`처럼 기능을 나타내는 문제 문구를 사용한다. 요음과 확장 가타카나는 하나의 학습 단위로 출제하며 구성 문자를 순서대로 쓴다.

## 7. 정보 구조

주요 이동 구조는 다음과 같다.

`홈 → 글자표 또는 연습 설정 → 쓰기 연습 → 결과`

모바일에서는 하단 탐색 메뉴, 데스크톱에서는 화면 폭에 맞춘 상단 또는 측면 탐색을 사용할 수 있다. 탐색 항목은 `홈`, `글자표`, `연습`, `기록` 네 개로 제한한다.

## 8. 화면 요구사항

### 8.1 홈

- `글자표 보기`와 `쓰기 연습 시작`을 가장 눈에 띄는 행동으로 제공한다.
- 오늘 연습한 문제 수와 최근 연습 문자를 표시한다.
- 히라가나와 가타카나의 연습 경험을 간단한 진행 상태로 보여준다.
- 첫 방문자는 기능을 설명하는 짧은 안내를 한 번만 볼 수 있다.

### 8.2 글자표

- 히라가나와 가타카나를 탭으로 전환한다.
- `기본`, `탁음·반탁음`, `요음`, `작은 문자·기호`, `확장 가타카나`로 필터링한다.
- 각 셀에는 큰 문자와 로마자를 표시한다.
- 문자를 선택하면 상세 패널을 연다.
- 상세 패널에는 문자, 한글 발음, 로마자, 분류, 획순, `이 문자 연습` 버튼을 표시한다.
- 모바일에서 셀과 버튼의 터치 영역은 최소 44×44 CSS 픽셀을 확보한다.

### 8.3 연습 설정

- 연습 모드: `따라 쓰기`, `암기 테스트`
- 문자 체계: `히라가나`, `가타카나`, `혼합`
- 범위: 전체 또는 글자표와 같은 그룹 단위 선택
- 문제 수: 5, 10, 20, 무제한
- 출제 방식: `균등 랜덤`, `덜 연습한 문자 우선`, `어려운 문자 우선`
- 유효한 문자가 하나 이상 선택되어야 연습을 시작할 수 있다.

### 8.4 쓰기 연습

- 상단에 진행 번호, 현재 문제, 종료 버튼을 표시한다.
- 중앙에 정사각형에 가까운 큰 쓰기 캔버스를 제공한다.
- 캔버스에는 보조선 표시를 켜거나 끌 수 있다.
- `지우기`, `한 획 되돌리기`, `정답 확인`을 제공한다.
- 사용자가 한 획도 쓰지 않았다면 정답 확인 전에 짧게 알리되 강제로 막지는 않는다.
- 화면 스크롤과 그리기 입력이 충돌하지 않도록 캔버스 위에서는 그리기 동작을 우선한다.
- 페이지를 떠날 때 진행 중인 세션이 있음을 확인한다.

#### 따라 쓰기

- 문제가 되는 가나를 크게 표시한다.
- 캔버스에 흐린 모범 문자 가이드를 선택적으로 표시한다.
- 획순 안내를 재생하거나 단계별로 넘길 수 있다.

#### 암기 테스트

- 정답 가나는 처음에 숨긴다.
- 한글 발음과 로마자를 함께 표시한다.
- 동음이거나 표기 규칙상 혼동될 수 있는 문제에는 문자 체계와 분류를 명시한다.
- 정답 확인 후 모범 문자와 획순을 표시한다.

#### 정답 비교와 자기 평가

- 작성한 선은 그대로 유지한 채 모범 문자를 반투명 오버레이로 겹친다.
- 오버레이 투명도를 조절하거나 켜고 끌 수 있다.
- 결과 선택은 `잘 썼어요`와 `다시 연습` 두 가지로 제한한다.
- 자기 평가 후에만 다음 문제로 이동한다.

### 8.5 연습 결과

- 완료한 문제 수와 자기 평가 성공률을 표시한다.
- `다시 연습`으로 표시한 문자를 목록으로 보여준다.
- `어려웠던 문자만 다시 하기`, `같은 설정으로 다시 하기`, `홈으로`를 제공한다.
- 무제한 모드는 사용자가 종료한 시점까지의 결과를 보여준다.

### 8.6 기록

- 전체 연습 횟수, 완료 세션 수, 최근 연습일을 표시한다.
- 문자별 연습 횟수, 성공 횟수, 다시 연습 횟수, 최근 연습일을 표시한다.
- `덜 연습한 문자`와 `어려운 문자` 목록을 제공한다.
- 기록 전체 삭제는 확인 단계를 거치며 삭제 후 복구할 수 없음을 알린다.

## 9. 핵심 동작 규칙

### 9.1 랜덤 출제

- 한 세션 안에서는 선택된 문자를 모두 한 번씩 섞은 뒤 출제한다.
- 선택 범위보다 문제 수가 많으면 한 순환이 끝난 뒤 다시 섞는다.
- 다음 순환의 첫 문제가 직전 문제와 같지 않도록 한다.
- `덜 연습한 문자 우선`은 연습 횟수가 적은 문자에 높은 가중치를 준다.
- `어려운 문자 우선`은 `다시 연습` 비율이 높은 문자에 높은 가중치를 준다.
- 새 사용자에게 기록이 없으면 두 우선 출제 방식 모두 균등 랜덤으로 동작한다.

### 9.2 캔버스 입력

- 하나의 포인터가 눌린 시점부터 떼는 시점까지를 한 획으로 저장한다.
- 좌표는 캔버스 크기에 대한 비율로 저장해 화면 크기가 바뀌어도 같은 모양을 유지한다.
- 실행 취소는 가장 최근 획 하나를 제거한다.
- 지우기는 현재 문제의 모든 획을 제거하되 세션 기록은 지우지 않는다.
- 정답 확인 전까지 사용자의 획 데이터는 현재 문제 상태에만 보관한다.
- 자기 평가가 끝나면 원본 획 좌표는 기본적으로 폐기하고 학습 결과만 저장한다. 개인의 필기 원본을 장기 저장하지 않는다.

### 9.3 학습 기록

문자별로 다음 값을 저장한다.

- 누적 출제 횟수
- `잘 썼어요` 횟수
- `다시 연습` 횟수
- 마지막 연습 시각

세션별로 다음 값을 저장한다.

- 시작·종료 시각
- 모드, 문자 체계, 선택 범위, 문제 수
- 완료 문제 수와 평가 결과 요약

진행 중 세션은 비정상 새로고침에 대비해 임시 저장한다. 사용자가 다시 방문하면 이어서 할지 새로 시작할지 선택할 수 있다.

## 10. 데이터 흐름과 구성 요소

### 10.1 데이터 흐름

1. 문자 카탈로그에서 필터 조건에 맞는 학습 단위를 선택한다.
2. 출제 엔진이 설정과 로컬 기록을 사용해 문제 순서를 만든다.
3. 캔버스가 포인터 입력을 획 단위 데이터로 관리한다.
4. 정답 비교기가 모범 글자와 사용자 획을 같은 좌표계에 겹친다.
5. 사용자의 자기 평가를 기록 저장소에 반영한다.
6. 결과와 기록 화면이 저장된 통계를 읽어 요약한다.

### 10.2 논리 구성 요소

- `KanaCatalog`: 문자, 발음, 분류, 획순 자산 관리
- `PracticeConfigurator`: 연습 조건 선택과 유효성 검사
- `QuestionGenerator`: 균등·가중 랜덤 출제
- `WritingCanvas`: 포인터 입력, 획, 실행 취소, 초기화
- `ModelOverlay`: 모범 글자 및 획순 표시
- `PracticeSession`: 현재 문제, 진행 상태, 평가 처리
- `LearningStore`: 브라우저 학습 기록 저장과 마이그레이션
- `ProgressSummary`: 문자별·세션별 통계 계산

각 구성 요소는 데이터와 UI를 분리해 이후 웹 UI를 iPhone UI로 바꾸더라도 문자 카탈로그, 출제 규칙, 기록 모델을 재사용할 수 있게 한다.

## 11. 로컬 저장과 개인정보

- MVP에는 계정과 서버 전송이 없다.
- 학습 기록은 현재 브라우저의 IndexedDB를 기본 저장소로 사용한다.
- 작은 환경 설정은 localStorage에 저장할 수 있다.
- 저장 데이터에는 이름, 이메일 등 개인 식별 정보를 포함하지 않는다.
- 브라우저 데이터 삭제, 시크릿 모드, 기기 변경 시 기록이 사라질 수 있음을 기록 화면에 안내한다.
- 데이터 구조에는 버전 번호를 둬 앱 업데이트 시 안전하게 마이그레이션한다.

## 12. 반응형 UI와 접근성

- 모바일 세로 화면을 우선 설계하며 최소 지원 폭은 320 CSS 픽셀이다.
- 쓰기 캔버스는 화면에서 가능한 가장 큰 정사각형 영역을 확보한다.
- 캔버스와 주요 버튼은 엄지손가락으로 누르기 쉬운 간격을 유지한다.
- 색상만으로 성공·재연습 상태를 구분하지 않고 글자나 아이콘을 함께 사용한다.
- 키보드만으로 글자표 탐색, 설정, 결과 평가가 가능해야 한다.
- 포커스 표시를 제공하고 스크린 리더용 이름을 지정한다.
- 동작 애니메이션을 줄이는 운영체제 설정을 존중한다.
- 획순 애니메이션 없이도 단계별 정적 안내를 볼 수 있게 한다.

## 13. 오류와 예외 처리

- 저장소를 사용할 수 없으면 앱 사용은 허용하되 기록이 유지되지 않는다고 알린다.
- 저장 데이터가 손상되면 사용 가능한 데이터만 복구하고, 불가능하면 확인 후 초기화한다.
- 획순 자산을 불러오지 못하면 문자와 발음은 계속 보여주고 획순만 사용할 수 없다고 표시한다.
- 선택 조건에 맞는 문자가 없으면 연습 시작을 막고 어떤 필터를 바꿔야 하는지 안내한다.
- 화면 회전이나 크기 변경 시 캔버스 획을 비율 좌표로 다시 그린다.
- 앱 업데이트 중 진행 세션 형식이 바뀐 경우 안전하게 종료 결과만 보존하고 새 세션을 시작하도록 안내한다.

## 14. 비기능 요구사항

- 중급 사양 모바일 기기의 모의 4G 환경에서 콜드 로드 기준 핵심 UI의 LCP가 2.5초 이내여야 한다.
- 글자표와 연습 기능은 설치 없이 브라우저에서 동작해야 한다.
- 동일한 입력 처리 코드로 마우스, 손가락, 스타일러스를 지원한다.
- 문자 데이터와 획순 자산에는 출처와 라이선스를 기록한다.
- 핵심 연습 흐름은 Safari, Chrome, Edge의 현재 및 직전 주요 버전에서 동작해야 한다.
- 가능하면 PWA 설치를 지원하되 MVP 출시의 필수 조건으로 삼지 않는다.

## 15. 테스트와 인수 기준

### 15.1 기능 테스트

- 모든 문자 항목에 표시 문자, 발음, 분류, 획순 데이터가 연결되어 있다.
- 필터 결과와 랜덤 출제 대상이 일치한다.
- 한 순환 안에서 불필요한 중복 문제가 발생하지 않는다.
- 따라 쓰기와 암기 테스트의 정답 노출 시점이 다르게 동작한다.
- 실행 취소가 마지막 획만 제거하고 지우기가 모든 획을 제거한다.
- 자기 평가가 문자별 기록과 세션 요약에 정확히 반영된다.
- 새로고침 후 기록과 진행 세션 복구가 동작한다.

### 15.2 입력·화면 테스트

- iPhone Safari에서 손가락 입력 중 페이지가 의도치 않게 스크롤되지 않는다.
- 데스크톱에서 마우스로 자연스럽게 선을 그릴 수 있다.
- 화면 회전과 리사이즈 후 획 위치가 유지된다.
- 320px 모바일 폭부터 넓은 데스크톱까지 핵심 버튼과 내용이 잘리지 않는다.

### 15.3 접근성 테스트

- 키보드만으로 홈부터 연습 결과까지 완료할 수 있다.
- 모든 주요 버튼과 필터에 접근 가능한 이름이 있다.
- 색상을 보지 않아도 상태와 선택 여부를 이해할 수 있다.

### 15.4 사용자 검증

입문자와 복습자를 포함한 소규모 테스트에서 다음 과업을 관찰한다.

1. 특정 가나의 발음과 획순 찾기
2. 히라가나 따라 쓰기 5문제 완료
3. 혼합 암기 테스트 10문제 완료
4. 어려운 문자만 다시 연습
5. 자신의 연습 기록 확인

별도 설명 없이 과업을 완료하지 못한 지점은 출시 전 우선 개선한다.

## 16. 개발 우선순위

### P0 — MVP 필수

- 문자 데이터와 글자표
- 연습 설정
- 포인터 기반 쓰기 캔버스
- 두 가지 연습 모드
- 모범 글자 비교와 자기 평가
- 랜덤 출제
- 로컬 기록과 결과 화면
- 모바일 반응형 UI

### P1 — MVP 품질 개선

- 획순 애니메이션
- 덜 연습한 문자·어려운 문자 우선 출제
- 진행 중 세션 복구
- PWA 설치와 오프라인 자산 캐시
- 기록 내보내기·가져오기

### P2 — 후속 버전

- 자동 손글씨 판정
- 계정과 기기 간 동기화
- 단계별 학습 코스
- 네이티브 iPhone 앱
- 단어 안에서 가나를 연습하는 문맥형 문제

## 17. 단계적 확장 방향

### 17.1 자동 손글씨 판정

MVP에서 축적하는 것은 정답 이미지가 아니라 자기 평가 결과다. 후속 판정 기능은 별도 검증을 거쳐 추가하며, 획의 형태뿐 아니라 획수와 방향을 어느 정도까지 평가할지 먼저 정의한다. 자동 판정 결과에는 확신도를 제공하고 사용자가 직접 수정할 수 있게 한다.

### 17.2 계정 동기화

로컬 기록 모델에 안정적인 문자 ID와 스키마 버전을 사용한다. 이후 계정 기능을 추가할 때 로컬 기록을 서버 계정으로 가져올 수 있게 한다.

### 17.3 iPhone 앱 전환

문자 카탈로그, 출제 규칙, 학습 기록 형식은 UI와 분리한다. 웹앱 사용 검증 후 다음 중 하나를 선택한다.

- 웹앱을 PWA로 강화해 홈 화면 설치 경험을 제공
- 웹 기술 기반 하이브리드 앱으로 패키징
- 공유 가능한 도메인 로직을 유지하면서 네이티브 UI로 재구현

iPhone 전환 방식은 웹 MVP의 터치 품질, 오프라인 요구, 앱스토어 기능 필요성을 확인한 뒤 결정한다.

## 18. 주요 위험과 대응

- **획순 데이터 품질과 라이선스:** 개발 시작 전에 사용할 데이터 출처와 재배포 조건을 검증한다.
- **터치 입력 지연 또는 스크롤 충돌:** Pointer Events와 실제 iPhone Safari 테스트를 초기 기술 검증 항목으로 둔다.
- **자기 평가의 주관성:** MVP의 목적을 판정이 아닌 반복 학습으로 명확히 안내하고 모범 글자 오버레이를 충분히 제공한다.
- **전체 문자 범위로 인한 콘텐츠 누락:** 문자 카탈로그 검증 스크립트와 목록 기반 테스트로 누락을 검사한다.
- **로컬 기록 손실:** 기록이 기기에만 저장된다는 점을 명확히 알리고 P1에서 내보내기·가져오기를 제공한다.
- **MVP 범위 확장:** 단어 학습, 계정, 자동 판정은 P0 완료 전 포함하지 않는다.

## 19. 출시 정의

다음 조건을 모두 만족하면 웹 MVP를 출시 가능한 상태로 본다.

1. 정의한 전체 가나를 글자표에서 탐색할 수 있다.
2. 모바일과 데스크톱에서 두 연습 모드를 완료할 수 있다.
3. 모범 글자 비교와 자기 평가가 학습 기록에 반영된다.
4. 새로고침과 재방문 후 기록이 유지된다.
5. 핵심 기능, 터치 입력, 반응형 화면, 접근성 테스트를 통과한다.
6. 문자·획순 자산의 라이선스가 확인되어 있다.
